# Market Intent Inference｜项目工程提示词草案

## 0. 项目定位

- 项目名：`market-intent-inference`
- 项目类型：科研工程混合的、可复现的市场微结构与交易意图推理平台
- 当前目标：先建立与交易场所无关的概率推理内核，再实现 BNB Smart Chain（BSC）meme coin 的 paper-only MVP
- 现有项目边界：与 `/Users/mashengyu/Desktop/quant research/coinman-arbitrage-bot` 完全隔离；不得修改、迁移、覆盖或依赖其未批准的运行状态
- 文档语言：简体中文；代码标识符遵循 Python 规范
- 当前阶段：设计审查；审查通过后进入基础框架实现

## 1. 核心目标

将市场参与者视为具有有限信息、不同约束和不同目的的策略主体。系统以可观测市场状态、历史事件、可选角色假设和可选已知操作为条件，输出：

1. 可能操作空间的概率分布；
2. 潜在操作意图的概率分布；
3. 角色假设的后验分布；
4. 证据、数据覆盖、校准状态和拒答原因；
5. 在交易约束、成本和风险条件下的理性决策或不交易结论。

Alpha 的定义：不是“预测价格”本身，而是利用市场微结构估计条件概率，并在执行成本、风险和能力约束下选择期望效用更高的行动。形式化为：

```text
P(R, A, Z | X, H, C)

R：角色假设
A：可执行操作
Z：潜在意图
X：当前可观测市场状态
H：历史事件序列
C：市场、账户、交易场所和策略约束
```

当操作已观测时，重点输出 `P(Z | X, H, R, A, C)`；操作未知时，输出 `P(A, Z | X, H, R, C)`。系统不得声称识别真实身份或真实意图，只能提供带证据和不确定性的条件后验。

每个预测必须显式包含 `decision_time`、`horizon_end`、`target_definition`、`event_position` 和 `data_cutoff`。所有特征必须满足 `as_of <= decision_time`；同一区块中决策点之后的交易不得进入特征。预测窗口和目标变量必须在实验配置中版本化。

## 2. 非目标

- 不把钱包地址直接等同于机构、散户、政府或其他真实身份；
- 不把“操纵”“诱多”“内幕”作为已证实事实，只能作为待验证假设；
- 不以 LLM 直接生成未经校准的概率；LLM 只能作为文本结构化、弱标签和解释辅助；
- 不在 MVP 阶段发送真实交易；
- 不把 BSC 现货自动做空或杠杆交易当作已支持能力；
- 不以单次回测盈利证明 Alpha 存在；
- 不修改现有 Coinman 项目。

## 3. 领域空间定义

### 3.1 场面状态空间 `MarketState`

状态由通用元素和 venue-specific 元素组成。每个元素必须记录 `value`、`as_of`、`source`、`quality`、`missing_reason` 和 `feature_version`。

通用元素包括：价格与收益、波动、成交量、成交方向、流动性、价差、冲击、资金流、市场阶段、跨市场关系、消息和基本面、时间周期、异常与数据质量。

CLOB 元素包括：多档 bid/ask、spread、mid/microprice、深度、深度不平衡、订单流不平衡、挂单、撤单、成交、队列位置、订单寿命、盘口斜率、流动性恢复和毒性流。

AMM/DEX 元素包括：池子储备、恒定函数/曲线参数、可执行报价、交易规模对应的价格冲击、池深度、LP 增减、Swap/Sync/Mint/Burn、代币 Transfer/Approval、区块内位置、Gas、路由、MEV 邻近交易、持仓集中度、合约权限、税费和卖出可行性。

消息/基本面元素包括：发布时间、来源、主题、情绪、事件类型、可信度、扩散速度、重复/转发结构、与资产的关联和可用时点。不得使用消息发布后的编辑内容污染历史时点。

### 3.2 玩家/角色空间 `RoleSpace`

角色是可证伪的行为假设，不是身份断言。基本集合：

- 流动性提供者/做市者；
- 知情或信息驱动交易者；
- 套利者；
- 短线动量/投机交易者；
- 逆势或均值回归交易者；
- 长期持有者/被动资金；
- 项目方/财库/早期持币者；
- 被迫卖出者或清算相关主体；
- MEV/区块排序相关主体；
- 交易所、路由器、桥和基础设施地址；
- 未知或混合角色。

角色只能基于行为、交易网络和公开标签形成概率分布。允许通过聚类、图特征和规则产生新角色候选，但新角色必须经过稳定性、可解释性和样本外验证后才能进入正式集合。

### 3.3 操作空间 `ActionSpace`

通用操作包括：买入、卖出、开仓、平仓、加仓、减仓、撤单、改价、对冲、套利和风险退出。`hold` 不作为已观测操作，而表示库存状态或 `no_observed_action`。

CLOB 操作包括：市价单、限价单、被动挂单、主动吃单、批量下单、撤单、分拆订单和跨市场执行。

AMM/链上操作包括：相对于明确 quote token 的 Swap 买入、Swap 卖出、加 LP、减 LP、转账、授权、路由切换、跨池套利、抢跑/夹子/回跑候选、合约管理操作和链适配的费用/优先级行为。多跳路由必须先标准化为完整路径，不能只依据单个 Transfer 判断买卖。

操作必须带有 `observed | inferred` 标记。链上已确认交易优先视为 observed；未上链的 mempool 行为只能作为低可靠性数据，不能当作已执行动作。

### 3.4 意图空间 `IntentSpace`

基本集合：

- 信息获取或信息驱动交易；
- 吸筹/累积；
- 派发/分销；
- 止盈；
- 止损或风险退出；
- 套利；
- 做市与库存再平衡；
- 对冲；
- 资金调仓/跨链/路由迁移；
- 流动性迁移或撤出；
- 项目方财库管理；
- MEV 提取；
- 诱导交易/操纵假设；
- 被迫交易或清算；
- 未知/多重意图。

标签分为三层：`observed_fact`（交易、事件、回执和合约状态）、`behavioral_hypothesis`（行为模式假设）和 `latent_intent`（不可直接验证的潜在意图）。`verified` 仅允许用于可直接观察的事实，不得用于真实角色或真实意图。真实意图不可观测时必须允许多标签混合和 abstain。每个标签还必须有 `known_true`、`known_false`、`unknown` 或 `not_supported` 语义。

## 4. 概率、标签与聚类原则

第一阶段采用可解释基线：条件频率 + 贝叶斯平滑 + 规则弱标签 + 校准层。之后可比较逻辑回归、树模型、序列模型和图模型。复杂模型必须与简单基线比较。

操作标签优先由订单、成交、链上事件和交易回执构造；意图标签通过规则、事件后结果、人工抽样和弱监督构造。不能把事后结果直接泄漏到事前预测特征中。

新元素发现流程：

```text
候选特征/事件 -> 行为向量 -> 聚类/密度分析 -> 稳定性检验
-> 解释命名 -> 样本外验证 -> 进入候选集合 -> 人工批准正式化
```

聚类不能直接被解释为新角色或新意图；必须同时报告簇大小、时间稳定性、跨资产稳定性、可解释特征、标签纯度和失败样本。

概率质量必须评估 log loss、Brier score、ECE、可靠性图、置信区间和 abstention coverage。交易决策必须使用校准后的概率，不得把分类分数伪装成概率。

## 5. Alpha 与理性决策

策略层使用预测后验、收益/损失分布、执行成本、风险预算、流动性、持仓和 venue capability 共同决策：

```text
选择 action = argmax E[utility(action) | posterior, costs, constraints]
```

如果期望效用不足、概率未校准、数据陈旧、流动性不足、合约风险过高或交易能力不支持，最优行动可以是 `no_trade`。

策略配置必须支持但不默认开启：只买入现货、现货双向、合约双向、杠杆区间、总资金、单笔风险、最大仓位、滑点、手续费、Gas、延迟和最大回撤。venue adapter 必须校验能力，不支持的组合直接拒绝。

## 6. BSC Meme Coin MVP

第一版限定为 BNB Smart Chain 主网（chain ID 56）的历史数据和 paper 回测；MVP 单一使用 PancakeSwap V2-compatible constant-product pools，配置显式固定 factory、router、quote token 和 ABI。V3、StableSwap、Infinity、聚合路由和 mempool 不属于 MVP。PancakeSwap V2 的官方开发资料提供 BSC factory/router 地址，但运行配置仍必须显式校验并允许更新。项目不发送交易、不管理私钥、不连接真实执行钱包。

第一批数据对象：区块、交易、交易回执、事件日志、BEP-20 Transfer/Approval、DEX PairCreated/Swap/Sync/Mint/Burn、池子储备、路由、Gas、钱包行为、持仓集中度、合约权限、LP 锁定/撤出和代币卖出可行性。

第一版操作：相对于 BNB/WBNB quote 的买入、卖出、加 LP、减 LP、转账、`no_observed_action` 和未知。

第一版角色：普通投机交易者、动量交易者、套利者、LP/做市者、项目方/早期持币者、MEV 候选、基础设施地址和未知。

第一版策略：现货、只做多、无杠杆的 paper 策略。做空、合约和杠杆只保留接口，不在没有明确 venue adapter 与真实历史数据前实现。

必须加入合约和代币风险状态：可卖出性、转账限制、黑名单/白名单、税费、铸币权限、暂停权限、管理员权限、LP 撤出、持仓集中度和疑似 honeypot/rug-pull 风险。每个风险字段只能输出 `known_true`、`known_false`、`unknown` 或 `not_supported`；风险评分只能作为过滤或权重，不得伪装成安全证明，`unknown` 不得解释为安全。

MVP 数据源通过显式 adapter 提供能力声明：数据源类型、可用区块范围、历史日志、历史 `eth_call`、receipt、trace、合约代码、完整性校验和缺失范围。能力不足时返回 `parked/unknown`，不得用未来数据或静默近似填充。BSC 的费用元素使用 `gas_price`、`gas_used` 和 venue-specific fee model，不固定使用 `priority_fee`。

## 7. 工程边界

目标分层：

```text
domain       纯领域模型、概率、标签、策略、风险和回测契约
application  数据编排、推理管线、聚类、校准、策略决策和实验运行
adapters     BSC/RPC/DEX/消息/存储/模型适配器
interfaces   CLI、API、报告和可视化
```

核心契约至少包括：`EventEnvelope`、`MarketState`、`VenueCapability`、`ObservedFact`、`BehavioralHypothesis`、`LatentIntent`、`Evidence`、`Posterior`、`RiskStatus`、`ConstraintSet`、`Decision` 和 `BacktestFill`。所有契约必须带 schema version、时间语义、来源质量和缺失原因。

回测决策以已确认区块的指定 `event_position` 为时点；成交只能发生在后续允许的事件/区块，并显式建模确认延迟、失败交易、滑点、手续费、Gas、token tax 和参与率上限。收益/损失分布必须由该执行模型产生，不得直接使用未来收盘价。

所有外部数据适配器必须有超时、重试边界、错误分类、缓存/快照策略和 parked 状态。原始数据、标准化事件、特征、标签、推理结果和回测结果分层存储。

每次运行保存：`run_id`、代码版本、配置哈希、数据源、链 ID、区块范围、最终性状态、模型版本、特征版本、标签版本、随机种子和产物清单。

项目必须与现有 Coinman 机械隔离：不得跨项目 import，不得共享数据库、`.env`、虚拟环境、运行目录或未批准 fixture；本项目不得读取或复用 Coinman 的未提交代码和运行状态。

## 8. 数据泄漏与回测门禁

- 特征时间不得晚于决策时间；
- 事件后标签只能用于训练目标或评估，不能回流特征；
- token universe 必须在各自决策时点确定；
- 风险评分不得使用未来权限变化或未来可卖出结果；
- 同一区块决策点之后的交易不得作为特征；
- 标准化器、校准器和聚类器只能在训练集拟合；
- 重叠预测窗口必须使用 purge/embargo；
- 按时间切分训练/验证/测试；
- 同时按 token 和市场阶段隔离训练、验证和测试，并加入未见 token 测试；
- 额外进行未见代币和未见市场阶段测试；
- 使用事件驱动回放，不使用未来收盘价假设成交；
- 决策时点固定在已确认区块的指定 event position；同一区块后续事件不可成交；
- 建模区块确认、RPC 延迟、交易延迟、滑点、手续费、Gas、token tax、失败/revert 交易和流动性上限；
- token universe、死亡 token、撤池 token 和幸存者偏差必须进入报告；
- 对低流动性 meme coin 使用参与率和容量约束；
- 与买入持有、随机/无信号、简单动量和风险过滤基线比较；
- 任何“有效 Alpha”结论必须同时通过样本外、成本后、稳定性和概率校准门禁。

## 9. 安全与交付门禁

- 默认 `paper=true`；禁止私钥进入代码、日志、Wiki、测试产物和 Git；
- MVP 不包含任何写链、执行或交易广播 adapter；`paper=false` 直接拒绝；
- 禁止 `eth_sendRawTransaction`、授权、资产转移和合约写方法；
- BSC chain ID、路由器、池子和 token 必须显式配置或白名单；
- RPC 响应、合约 ABI、事件日志和模型输出先校验再使用；
- 不做真实下单、资产转移、授权或合约写操作；
- 设计、独立审查、用户批准、实现计划、TDD、Harness Eval、Research Wiki、Graphify 和完成前新鲜验证均为必经门。

## 10. 初始验收标准

1. 能用固定 fixture 生成统一市场事件、状态、角色、操作和意图对象；
2. 推理输出可重复、可解释、概率归一化并能 abstain；
3. 能完成 BSC 历史事件回放和 paper 回测；
4. 能证明核心特征无未来数据；
5. 能输出概率质量指标和成本后策略指标；
6. 聚类新元素只进入候选集合，不能自动改变生产标签；
7. 现有 Coinman 工作区内容保持不变。
